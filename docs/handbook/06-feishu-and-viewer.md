# 6. 飞书图片交互与手机预览

文档整理：**Zhuofan Xie** · 2026-10-08

[返回主目录](README.md)

## 6.1 两条网络链路，不能混为一谈

```text
手机 → 飞书平台 ← 电脑主动建立长连接：指令、附件、回复
手机浏览器 → 电脑 Viewer：读取空间照片图层和交互页面
```

飞书能收到消息不代表手机能访问电脑的 192.168 地址。
长连接解决事件接入，不会自动为 Viewer 提供公网路由。

电脑是完整节点：Web、Agent、飞书、数据、Viewer 和模型部署到同一目标机；
不是依赖另一台 Mac 作固定控制入口。模型 Provider 可以作为该机器的隔离进程/容器。

## 6.2 配置顺序与每步验收

| 顺序 | 操作 | 成功标志 | 为什么 |
| --- | --- | --- | --- |
| 1 | 开放平台创建企业自建应用，启用机器人 | 可见 App ID/应用能力 | 不是群里简单 Webhook 机器人 |
| 2 | 配置文本、图片资源及发送能力 | 应用权限与 API 需求对应 | 接收文本、下载图片、上传结果是不同权限 |
| 3 | 长连接事件 im.message.receive_v1 | 平台已保存事件配置 | 确保消息事件送达 |
| 4 | 回调配置 card.action.trigger | 卡片按钮回调已订阅 | 这是回调，不是普通消息事件 |
| 5 | 发布新版本，设置可用范围/审批 | 测试成员可使用应用 | 勾选后台权限不代表运行版本已授权 |
| 6 | Web 外部接入填写凭证、测试并启用 | 运行状态 connected | 测凭证成功不代表业务事件成功 |
| 7 | 获取用户 Open ID 加入本地白名单 | 工作区启用，新消息获准 | 飞书可用范围与本地授权是两层 |
| 8 | 私聊文本、图片、结果各测一次 | 三段分别成功 | 禁止只测“你好”就宣布媒体验收 |
| 9 | 群里拉入机器人，开启群 @ 策略 | 每位授权用户 @ 能执行 | 群开关、@、可用范围、白名单缺一不可 |

具体操作、后台截图位置、权限示例见
[飞书配置指南](../guides/feishu-setup.md)。
新增 Open ID 必须取当前应用真实返回值，不用姓名、手机号或旧机器人的 ID 替代。

平台权限名和范围会变化，应以当前应用身份和对应官方接口的“权限要求”为准：
[资源下载](https://open.feishu.cn/document/server-docs/im-v1/message-resource/get)、
[图片上传](https://open.feishu.cn/document/server-docs/im-v1/image/create)。
本轮官方资源页未返回可读正文，因此不把旧权限清单当已重新核验的完整最小集合；
遇到拒绝按真实响应码与缺失 scope 修正，发布/授权后发一张新图测试。

## 6.3 代码如何处理一条消息

在 [feishu.py](../../backend/app/feishu.py) 中顺序阅读：

```text
_on_message
  → 检查事件字段和 bot 来源
  → SQLiteChannelStore.claim_message：持久化去重
  → record_event：授权消息摘要；未授权/停用用户不保存正文
  → _spawn(_process_message)：快速离开接收回调
_process_message
  → Open ID 白名单 / 工作区状态 / 群 @ 策略
  → 处理审批、菜单、多图草稿、图片或普通 Agent
  → asyncio.to_thread 等方式避免同步执行占住事件循环
  → 回复确认/结果，记录渠道事件
```

[identity.py](../../backend/app/identity.py) 负责工作区映射；
`_thread_id(chat_id, sender_id)` 负责会话区分。群里不同用户不能共用同一规划历史。

当前 Web 渠道时间线读取 channel_events；与 Web agent_messages 仍不是完全统一的一张消息事实表。
管理员可见不代表普通用户间可以互相召回。
授权用户的文本摘要仍可能包含个人内容；`record_event()` 的截断和媒体路径限制不是通用脱敏。
渠道数据库与导出轨迹不能直接作为公开 Issue 附件。

## 6.4 图片进入系统之后是什么

平台传来的是资源引用，不是可直接放给模型的本机路径：

1. `_image_resource_entries()` 解析图片/富文本附件；
2. `_download_image_resource()` 依次尝试消息资源、图片和 SDK 下载路径；
3. 后端安全解码、移除原始元数据、缩放并暂存；
4. 单张空间图片绑定 source_image_id；
5. 风格化草稿按 owner/chat 区分内容图与参考图；
6. 创建持久化 Job，发送任务确认；
7. 任务完成后渠道 Presenter 回传结果。

资源引用只在下载时使用。没有权限时不能把“更换下载接口”当权限绕过。
详情与多图角色见 [媒体能力 SOP](../guides/feishu-media-capability-sop.md)。

## 6.5 两种生成结果，分别如何返回

| 类型 | 飞书聊天里看到什么 | 交互在哪 |
| --- | --- | --- |
| 空间照片 | 任务确认、封面图、结果卡片、Viewer 地址/刷新入口 | 浏览器中的分层视差 |
| 图片风格化 | 草稿、任务状态、生成结果图和文件/重试入口 | 主要是静态结果浏览与下载 |
| Flux-GS | 数据集/部署说明、训练状态、结果预览地址 | 独立 Provider 对应 WebGL；真实链路需部署 |

飞书图片消息是静态媒体，不会把 PNG/JPEG 变成 3D。
需要交互必须另开 Viewer；视频只能演示固定运镜，也不等于自由视角。
当前不能把计划中的 turntable/MP4 当已经存在的自动输出。

阅读 `_deliver_spatial_job_result()`、`_deliver_photo_style_result()`、
`_send_image()`、`_send_file()`、`_send_card()`。

## 6.6 手机 Viewer 的配置与安全

默认 Viewer 按需监听 8766；API 和 Root 网页仍应仅本机访问。
[lan_viewer.py](../../backend/app/lan_viewer.py) 的 `create_link()` 按以下优先级选地址：

```text
LAN_VIEWER_PUBLIC_BASE_URL
→ 仍有效的运行时 HTTPS 隧道地址
→ 选出的局域网 IP:8766
```

先验收局域网：

1. 手机/电脑接入同一网络，不用蜂窝网络访问私有 IP；
2. 检查 Wi-Fi AP 隔离/VPN/防火墙，不是“同名 Wi-Fi”就一定互通；
3. 在手机打开新的结果链接；
4. 先验证触摸拖动，再验证倾斜。

默认 HMAC 签名含 asset_id/到期时间，TTL 12 小时，可配置但上限 7 天。
`viewer-secret.key` 持久化让重启后签名不自动换钥，但不取消链接到期；
资产删除、地址变化、隧道退出仍会失效。签名是持有者凭证，不是用户登录，也不会加密图片内容。

公网使用固定 HTTPS 域名/受控代理，或明确的临时测试隧道。仅暴露只读 Viewer，
不要反向代理整个 Root API。买域名本身不让睡眠/断网的电脑持续在线。
目前固定域名、身份化分享/撤销和长期运行是上线计划，不在本章声称已经完成。

## 6.7 倾斜没反应为何不一定是模型问题

设备姿态 API 的支持、权限和 HTTPS 安全上下文由浏览器控制；
需要权限的浏览器应从用户点击“开启倾斜”触发请求，不能页面加载时擅自申请。
本机代码同时做方向换算、初始姿态校准、死区、限幅和平滑，触摸作为兜底。

参考 [MDN requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static)。
飞书内置浏览器与 Safari/Chrome 的表现需分别验收，不从电脑鼠标效果推断手机已通过。

## 6.8 故障按层排查

| 表现 | 首先查哪层 | 不该怎么做 |
| --- | --- | --- |
| 无入站记录 | 应用发布、事件、连接、网络 | 立刻改 LLM Prompt |
| 有拒绝事件 | 白名单、工作区、群 @ | 开放给全部未知用户 |
| 收到图片但下载失败 | 资源接口响应码、权限、图片引用 | 输出 App Secret 帮忙调试 |
| Job failed | 模型/环境/输入/日志 | 把“图片权限”当生成模型问题 |
| Job completed 无封面 | 资源上传/消息发送/回传路径 | 重新跑一遍生成代替重发 |
| 链接打不开 | 地址可达、服务在线、签名 | 仅增大 TTL |
| 可打开但倾斜无效 | 浏览器权限/HTTPS/姿态支持 | 重新训练深度网络 |

长连接已支持连接/重连状态和有界发送重试，`_send_with_retry()` 保留 SDK UUID；
接收回调创建的 asyncio task 和结果发送仍非完整持久化 Outbox。
进程退出后不能保证所有未发通知自动恢复；生产化应把待发项、去重键、状态、退避和死信落库。

## 6.9 首响指标如何理解

历史 PERF-001 中 23 条本地事件首响 P95=1.191s；
它从本机入站记录到首条出站记录，不包含完整手机显示时延。
同源空间任务的早期确认 0.904s 与最终卡片 15.675s，等待差约 94.2%；
这是同流程的反事实比较，不是独立 A/B，也不是模型推理加速。

完整手机体验还应测上传、排队、生成、封面发送、点击 Viewer、页面加载和首次可交互时间。
